# Mission Reflection

**1. Which cloud infrastructure component do you think is the most important? Why?**

Compute is the most important component, since it is the resource that 
actually executes applications and processes data. Storage and networking 
support compute by holding data and enabling communication, but without 
processing power, none of the other components would have anything to do. 
Compute also tends to be the most expensive and most scaled resource in a 
cloud deployment, making it central to both performance and cost decisions.

**2. How does Linux support cloud computing?**

Linux is lightweight, open-source, stable, and highly customizable, which 
makes it the preferred operating system for most cloud servers. Its low 
resource overhead allows more virtual machines to run efficiently on the 
same physical hardware, and its strong command-line tools make it easy to 
automate configuration, monitoring, and deployment tasks at scale.

**3. Why is technical documentation important before deploying infrastructure?**

Documentation ensures that design decisions are recorded, justified, and 
understood before resources are committed. It helps engineering teams avoid 
miscommunication, supports troubleshooting later on, and gives future team 
members the context needed to maintain or scale the system without having 
to reverse-engineer decisions from scratch.

**4. What new skills did you learn during this laboratory activity?**

I learned how to investigate a Linux server's hardware and software 
configuration using terminal commands, how to identify and describe cloud 
infrastructure components, and how to compare infrastructure services across 
AWS, Azure, and GCP. I also gained hands-on experience with Git and GitHub, 
including resolving merge conflicts and authenticating with a personal 
access token.

**5. How has your GitHub portfolio improved after completing this mission?**

My portfolio now includes a second structured laboratory folder with clear 
documentation, a diagram, and organized Markdown files, showing consistent 
version control practice through multiple commits. This reflects growth in 
both my technical understanding of cloud infrastructure and my professional 
workflow for documenting and submitting engineering work.
